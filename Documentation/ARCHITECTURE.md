# Структура Unity-проекта

Человекоподобные враги используют атласы 35×35: `enemy_{variant}_{action}_{direction}` и `boss_{kind}_{action}_{direction}`. Движение — 6 кадров в четырёх направлениях; атака — 8, бросок — 6, только влево/вправо. `EnemySystem` задаёт несохраняемые поля подготовки/возврата в `Enemy`, а `CampaignRenderer.DrawAnimatedEnemy` выбирает кадр и оружие. Момент нанесения урона и выпуска снаряда остаётся в прежних правилах AI. Исходники Aseprite лежат в `ArtSource`; спрайтшиты — в `Assets/Hobo/Resources/Art`.

Текущий приоритет: поддерживаемый код и ассеты первой главы. Расширение кампании приостановлено по просьбе автора. Наличие восьми наборов встреч не означает готовую игру на 6–8 часов.

## Где что менять

Все игровые исходники находятся в `Assets/Hobo/Runtime`.

| Файл / каталог | Ответственность |
| --- | --- |
| `CampaignGame.cs` | Создаёт зависимости, передаёт ввод в симуляцию, обновляет представление. Не содержит правил боя и генерации звука. |
| `CampaignModel.cs` | Сессия, порядок обновления систем, загрузка комнат, переходы кампании. |
| `Input/PlayerInputReader.cs` | Клавиатура, мышь, геймпад. Возвращает `InputFrame`. |
| `Gameplay/RoomSetup.cs` | Начальная расстановка противников и предметов; отдельная политика прототипа. |
| `Gameplay/PlayerSystem.cs` | Движение игрока, таймеры действий, баффы, выполнение команд ввода. |
| `Gameplay/EnemySystem.cs` | Решения противников, подготовка атак, преследование. |
| `Gameplay/CombatSystem.cs` | Дальность и сектор удара, блок, урон, смерть и выпадение оружия. |
| `Gameplay/ProjectileSystem.cs` | Полёт, столкновение и завершение бросков/выстрелов. |
| `Gameplay/ArenaNavigation.cs` | Проверки геометрии, движение без прохождения сквозь стены, поиск пути. |
| `Gameplay/InventorySystem.cs` | Подбор, смена оружия/одежды, применение напитков, взаимодействие с чекушкой. |
| `Saving/CheckpointStore.cs` | JSON, валидация состояния, атомарная замена сохранения, восстановление. |
| `Audio/GameAudio.cs` | Временные звуковые эффекты и громкость. Подписан на сигнал сессии. |
| `UI/CampaignUI.cs` | HUD, меню, пауза и кнопки uGUI. |
| `Presentation/CampaignRenderer.cs` | Спрайты, порядок отрисовки, декорации. Не меняет HP и решения AI. |
| `Data/` | Отдельный файл для каждого типа данных; правила предметов и противников. |
| `Editor/CampaignChecks.cs` | Регрессионные проверки без зависимости от ввода рабочего стола. |
| `Editor/HoboSetup.cs` | Подготовка сцены и сборка Windows. |

## Зависимости

`CampaignGame → ввод → CampaignModel → игровые системы`.

Состояние читают `CampaignRenderer` и `CampaignUI`. Звук получает сигнал через делегат; игровые системы не создают AudioSource, Canvas или SpriteRenderer. Системы — обычные C#-объекты, представление и звук — Unity-компоненты.

Системы пока используют общий объект сессии. Это явная упрощённая архитектура прототипа, а не полностью изолированная доменная модель. Не создавать универсальный singleton, глобальную шину всех событий или десятки интерфейсов без реальной необходимости. При росте системы выделять зависимость по конкретной потребности.

## Правила дальнейшей работы

- Одна ответственность на класс, одно определение типа на файл.
- Не возвращать боевую логику, звук и UI в `CampaignGame`.
- Писать обычные многострочные методы с понятными именами, не упаковывать класс в строки.
- Данные сохранений менять с учётом версии формата.
- С 6 ноября 2026 по просьбе автора не запускать игру, тесты и поиск багов; проверку выполняет команда.
- Доступ к компьютеру разрешён; предпочитать API/CLI без лишнего переключения фокуса.

## Ассеты

`ArtSource/` — исходники Aseprite. `Assets/Hobo/Resources/Art/` — PNG для игры. Палитра и масштаб описаны в `STYLE.md`. Новые ассеты первой главы хранить отдельно до визуального просмотра; не подменять сразу всю графику.
